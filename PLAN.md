# PipeTwin. План конкурсного решения

Ревизия от 13 ноября 2026 года после критического разбора данных и литературы. Цель — повысить качество пространственного прогноза и подготовить полную воспроизводимую сдачу. Приоритет методов определяется результатами исторических проверок. [Аудит](docs/data-audit.md), [реестр противоречий](docs/inconsistencies.md), [размерности](docs/units-and-dimensions.md), [литературный обзор](docs/literature-review.md) и [16 серий экспериментов](docs/experiments.md) образуют единый план. Код каркаса содержит комментарии.

## Что сдаём

| Артефакт | Условие готовности |
| --- | --- |
| `result.csv` | Ровно три колонки `id,segment_id,thickness_pred`, одна строка на каждый 10-метровый сегмент двух зачётных труб. Толщина в мм, десятичная точка, все значения конечны, ключи совпадают с эталонным списком. |
| Код | Один документированный запуск от локальных исходников до `result.csv`. Зафиксированы зависимости в `requirements.txt`, seed, конфигурация и схема валидации. Проверка на обычном ноутбуке, запасной вариант Google Colab. |
| README | Как воспроизвести результат, какие поля и правила очистки использованы, как получены оценки, какие допущения остались. |
| Защита | До 10 слайдов, 5 минут доклада и 3 минуты вопросов. Репетиция с вопросами по геометрии, 2018 году, утечкам и переносу на новую трубу. |

Рубрика даёт каждому из четырёх обязательных элементов по 0–10 баллов. Кейс задаёт квадрат корреляции Пирсона отдельно по каждой трубе. Для защиты готовим графики прогноз–факт, продольный профиль, таблицу моделей по горизонтам, список 10% участков для первоочередной проверки и интервалы P10–P90 с проверкой покрытия.

## Порядок работы

1. **Зафиксировать контракт данных.** Получить два зачётных ID, их уровень в иерархии POT, даты T и эталонный перечень сегментов. Установить правила ВТД и cold start из [журнала вопросов](docs/data-audit.md#вопросы-организаторам). Параллельно строить пробную сегментацию и временные срезы по историческим кампаниям. Критерий перехода к официальному экспорту — подтверждённые ключи, длины и даты. Пробный экспорт помечать как исторический.
2. **Собрать воспроизводимый минимум.** Каноническая сетка, таргет, снапшоты на даты отсечения, матрица допустимых проверок ниже, базовые модели и проверка экспорта. Между ВТД сравнить перенос последней толщины, общую скорость как контроль калибровки и локальный рост с усадкой к общей оценке. Для cold start сравнить номинал, индекс экспозиции и Ridge на разрешённых признаках. Добавить CatBoost малой глубины. Критерий готовности — сквозной запуск из входных файлов, результаты по каждому доступному фолду и необходимые тесты контракта.
3. **Улучшать по одной гипотезе за запуск.** Первый приоритет после минимума — сглаживание прошлого профиля, локальная усадка, небольшой GAM и размерностно согласованные признаки режима. Затем сравнить прямой прогноз с моделью состояния и ошибки ВТД. Matching, модель обнаружения и экстремумы подключать по наличию требуемых данных. Вести журнал запусков с гипотезой, версиями данных, признаками, фолдами, длительностью и решением. Каждый новый источник оценивать абляцией на одинаковых ключах.
4. **Сравнить ансамбли и устойчивость.** Сначала зафиксировать одиночных кандидатов на разработочных блоках. На внутренних OOF сравнить фиксированную смесь, блендинг и простой стекинг. Проверить чувствительность к неизвестной ранней экспозиции, ошибкам измерения и привязки. Зафиксировать выбранный метод, веса и конфигурации до поздней проверки. Если дальнейшая настройка использует её результаты, пометить цикл исследовательским. [Протокол ансамблей](docs/experiments.md#блендинг-и-стекинг).
5. **Собрать сдачу.** Проверить файл против шаблона и воспроизвести его из чистого окружения. Сохранить таблицу сравнения и объяснения худших ошибок. Вынести в отдельные артефакты список для инспекции, интервалы и графики. Собрать защиту вокруг двух сценариев и того, какие эксперименты повлияли на выбор модели.

## Канонические данные и признаки

- Сохранить происхождение строки, исходный ID, единицы, дату наблюдения и дату доступности, если она известна. Привести ID к строкам без хвоста `.0` после проверки целочисленности. Разрешённые поля хранить отдельно по двум сценариям. Режимные поля POT исключить из исторических признаков, их совпадение со снимками TECH 2024 года подтверждено. Все метаданные с неизвестной доступностью к исторической дате исключить из первой модели. Для ввода, ремонта и смены металла вести эпохи.
- Построить сетку по независимой паспортной геометрии и шаблону. При подтверждении локального начала использовать `floor(s / 10)` для `0 ≤ s < L`, укороченный конечный сегмент для дробного остатка, отдельное правило для точки ровно `L`. Для зачётной магистрали установить порядок простых участков, направление и смещения. При несовпадении источников хранить диагностику привязки и отправлять спорные строки в карантин. Запретить перенос точек за границей в ближайший сегмент без правила.
- Для каждого ВТД агрегировать минимальную измеренную остаточную толщину среди допустимых записей сегмента. При переменном номинале минимум вычислять по локальным остаткам, а не через один средний номинал. Проверить сценарии точки и пересечения по длине дефекта, если известен смысл координаты и правило жюри. Хранить статусы наблюдаемого значения, обследования без регистрации, неизвестного охвата и исключения по качеству. Цензурирование требует подтверждённого охвата и модели обнаружения. Плотность и геометрию дефектов целевого ВТД ограничить построением метки и диагностикой.
- Для случая между ВТД модель получает последнюю наблюдавшуюся толщину, признаки её доступности и, где разрешено, историю дефектов и ближайших сегментов. Для cold start отдельный контракт включает подтверждённый паспортный номинал и режим. Рельеф подключать после уточнения допустимости, иначе запускать строгий вариант без него. Расчётные P/T между началом и концом простого участка использовать как сценарную интерполяцию после проверки направления и единиц.
- Признаки режима считать по календарным окнам и горизонту с оценкой покрытия: квантили, доли активной работы и простоев, эпизоды длительного контакта с водой, интегралы экспозиции с ограничением переноса через длинные пропуски. Сохранить суммарное число наблюдавшихся дней и возраст трубы отдельно. Дни без данных учитывать отдельно от нулевого расхода. Признаки рельефа, если разрешены, включают локальные уклоны по потоку, впадины и подъём до следующего перегиба. Дистанцию и ID не использовать как замену механизму коррозии при переносе.

Точное число оцениваемых сегментов пересчитать после утверждения сетки и фильтра типов. До этого приведены контрольные числа аудита. Распределения целей 2023 уже просматривались при проверке качества, прогнозные метрики моделей ещё не рассчитывались. Поздняя кампания является проверкой после аудита, полную независимость от разработки подтверждает только скрытая оценка организаторов.

### Значение конкурсной метрики

При конечных неконстантных рядах `corr(y,a×prediction+b)²=corr(y,prediction)²` для любого ненулевого a. Поэтому общий сдвиг толщины или единая скорость на общем горизонте сохраняет Pearson². Обратный знак также скрывается квадратом, поэтому signed r обязателен. Калибровка в мм нужна для содержательного прогноза, а прирост конкурсной метрики требует улучшения пространственной формы. Нелинейное ограничение диапазона может менять корреляцию и проверяется отдельным опытом.

Для learned-кандидатов сначала сравнить MSE и Huber, абсолютный остаток и потерю доли стенки с восстановлением мм. Процентные цели задают другие веса ошибок при неоднородном номинале. Ранжирование тонких сегментов оценивать отдельно. Усложнять loss под Pearson только при устойчивом преимуществе на внутренних блоках.

- **Между ВТД.** Внешняя проверка последовательными датами. Для цели 2022 использовать для обучения только метки, ставшие известными до 2022; при отсутствии доступных пар показать лишь базовые методы с заранее заданными правилами. Для цели декабря 2023 можно учить динамику на 2018→2022. Считать допуск режима до T как ретроспективный сценарий по условиям кейса, а режим до даты прогноза — отдельный эксперимент, если нужен прогноз без уже измеренного режима горизонта. Признаки из ВТД брать строго раньше целевой кампании. Дополнительно проверять перенос между простыми участками и целыми группами, когда такой фолд возможен.
- **От ввода до ВТД.** Удерживать всю магистраль или направление с родственными участками, на удержанной группе использовать только первый допустимый ВТД как метку. В обучении проверять даты и применять тот же контракт доступности. ВТД 2014 года исключить из основной cold-start проверки до уточнения даты ввода, альтернативную трактовку показывать отдельно. При невозможности получить независимый и хронологически допустимый фолд обозначить эксперимент как ретроспективную диагностику. Малая выборка труб ограничивает выводы о переносе.
- **Пространственная зависимость.** Использовать непрерывные блоки и буфер не меньше максимального радиуса признаков, matching или сглаживания. Проверить разумный диапазон длин блока по автокорреляции на обучении. Соседние сегменты одной трубы не делить случайно. В повторном прогнозе прошлые ВТД удержанной трубы допустимы как признаки на инференсе, если они были известны к T. Метки удержанной кампании и характеристики её покрытия исключить из всех преобразований и подбора.
- **Отчёт.** По каждому кейсу, фолду и доступному диапазону горизонтов вывести число сегментов и независимых труб/кампаний, покрытие таргета, signed Pearson `r`, его квадрат, MAE, RMSE, среднюю ошибку и recall@10% среди самых тонких сегментов. Константный прогноз или факт помечать как неопределённую корреляцию до уточнения жюри. Отдельно показать по сегментам без истории и по наиболее тонкой части распределения. Не трактовать среднюю по всем строкам как конкурсный балл.
- **Выбор.** Сравнивать одинаковые ключи и горизонты, показывать результаты по каждой группе. Повышение Pearson² должно сопровождаться положительным `r` и приемлемой ошибкой толщины и ранжированием. До запуска пакета определить правила разрешения конфликта метрик и предел ухудшения MAE относительно baseline. Порог выбрать из инженерного допуска или согласованного относительного изменения, пометить его как наше решение. Для оценки разброса использовать пространственные блоки при их достаточном числе. Широкие интервалы и противоречащие фолды отражать в выборе более простого кандидата.

### Бюджет и последовательность

Для первого рабочего цикла предлагается распределить усилия примерно 30% на контракт и валидацию, 25% на минимум и простые модели, 25% на выбранные улучшения, 20% на воспроизведение и защиту. Это рабочая оценка до получения срока и вычислительных ресурсов. Начальный пакет ограничить persistence, общей скоростью, локальной усадкой, Ridge/GAM и CatBoost с небольшим заранее записанным набором настроек. Новое семейство добавлять после проверки конкретной причины ошибки. Все 16 серий образуют очередь гипотез, запуск каждой не является условием готовности.

## Проверки перед сдачей

- Синтетические примеры для сетки и её границ, перехода между метрами и километрами, привязки даты, единиц глубины ВТД, пропусков и ремонтов. Проверить, что удаление или подмена запрещённых будущих строк оставляет признаки на старую дату идентичными.
- Для экспорта сверить множество ключей с шаблоном, порядок колонок, отсутствие дубликатов, дополнительных строк, пропусков, отрицательных и бесконечных значений. Проверить локальные верхние границы по подтверждённому номиналу, допускам и заменам. Локальная геометрия и события ремонта могут изменить допустимую толщину.
- Для дополнительных материалов подготовить разбивку ошибок по участкам и срезам, чувствительность к выбору таргета, важность блоков признаков через абляции. Топ-10% считать отдельно по каждой трубе по малой прогнозной толщине с правилом для совпавших значений. При подтверждённых эксплуатационных порогах дополнительно показать приоритет по вероятности их нарушения. Интервалы и приоритеты хранить отдельно от `result.csv`.
