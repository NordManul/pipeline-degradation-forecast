## Подтверждено пользователем: ретроспективное восстановление

Для интеграции рекомендован исследовательский кандидат
`forest_log_rate_balanced_seed42` из [расширенного поиска](BROAD_CASE2_RESULTS.md).
Модель получает `position_fraction` и `altitude_relative_m`, учит
`-log(y_mm / nominal_mm) / horizon_years` и восстанавливает толщину
экспонентой. Вес наблюдения обратно пропорционален размеру наблюдаемой
кампании. Сохранён кандидатный CSV для кейса 2 и сериализованная модель в
`artifacts/agent2_physics/case2-broad-delivery/`. Проверка по
удержанным MAIN улучшила r/MAE относительно CatBoost. Скрытая оценка ещё
нужна для измерения качества на MAIN-4.

14 ноября 2026 пользователь ответил: **«Восстановление состояния: поздние
данные других труб разрешены»**. Повторное разрешение на эти метки не требуется.
Для новой постановки прежний запрет обучения после 2022-07-01 отменён.
Дата состояния целевой трубы остаётся 2022-07-01; её признаки не получают
поздних TECH или ВТД. Старые строгие результаты сохраняются как отдельный режим.

[Протокол исследования](RETROSPECTIVE_PROTOCOL.md) и runner
`python -m pipetwin.agent2_physics.retrospective_case2` реализованы в пакете агента 2.
Используются общие cleaner, canonical_snapshot, build_exposure, модели и scorer;
LeaveOneGroupOut берётся из sklearn. Для интеграции основному агенту нужно
разделить `target_state_date` и `training_data_available_until`, добавить
подготовку всех cold-кампаний и проверку целой MAIN со всеми её датами.
Общий контракт не переписывался; модельный API совместим, временная политика
исследования является явно разрешённым расширением строгого контракта 1.0.0.

## Приоритеты после диагностики кейса 2

Подробные доказательства и результаты: [CASE2_DIAGNOSIS.md](CASE2_DIAGNOSIS.md).

1. В текущем `configs/case_benchmark.yaml` guard не включён: agent2_options
   задаёт только missing_policy. Включить `residual_guard: train-bounded`
   для остаточного кандидата либо исключить его до проверки. Иначе обычный
   запуск сохраняет известную неустойчивую экстраполяцию; clipping её скрывает.
2. Режим обучения теперь подтверждён: ретроспективный
   перенос по всем выданным кампаниям. Для интеграции разделить
   `target_state_date` и `training_data_available_until` в новой версии контракта.
   Текущий prepare_case жёстко берёт cold 2018; clean_sources и validate_package
   связывают target с cutoff. Просто заменить cutoff или убрать проверку нельзя.
3. Для расширенного пула подготовить все кампании как cold-снимки без истории
   ВТД в признаках, затем удерживать целую MAIN со всеми её датами. Этот режим
   проверки должен быть отдельным от четырёх пространственных фолдов MAIN-2.
4. Все ячейки MAIN-4 сейчас имеют один режим. Запросить гидравлическую привязку
   локальных режимов и срок действия TECH-снимка. Проверить покрытие неизвестной
   истории: диагностический observed-only сильно переоценивает переносимую
   скорость по сравнению со сценарием train-median. Это не основание молча
   считать train-median истинной историей или выбрать его по скрытой цели.

В диагностике MAIN-3 CatBoost с train MAIN-2 2018+2022 получил r=0,293173,
MAE=0,206177 мм (раньше r=0,138107, MAE=0,243889), но RMSE/recall thin-10%
не улучшились. Это основание проверить pooled cold CatBoost, а не утверждать
подтверждённый выигрыш на скрытой MAIN-4. Официальные конфиги здесь не менялись.

```python
from pipetwin.agent2_physics import make_model

model = make_model(
    "positive_rate", scenario="cold", exposure=case2_exposure,
    cutoff_exclusive="2022-07-01T00:00:00", feature_columns=case2_allowlist,
    seed=42, options={"missing_policy": "observed-only"},
)
model.fit(train_frame, train_y_mm)
prediction_mm = model.predict(request_frame)
```

Переменные данных в примере предоставляет общий конвейер. Exposure сразу содержит
нужные train/validation/inference истории. Выбор выполняется по exposure_id.
Неиспользуемые истории не влияют на fit. При обращении к истории её календарь,
участок и доступность проверяются полностью.

## Настройки

- Эксперимент этапа 3: `cold_nominal_scaling="none"` (по умолчанию) или
  `"train-relative"` только для cold. Опорный номинал — train-медиана,
  скорость в мм/год и годовая остаточная поправка умножаются на отношение
  номиналов. `diagnostics_` сохраняет reference_nominal_mm и единицы.
- `residual_feature_map="identity"` (по умолчанию) или `"terrain-symmetric"`
  только для hybrid_residual с allowlist ровно `slope_50m`, `lowpoint_depth_m`.
  Второй режим использует модуль уклона и глубину понижения; имена преобразованных
  признаков отражены в диагностике. Порядок исходного allowlist несущественен.
- **Не включать новые опции по умолчанию:** [этап 3](CASE2_SEARCH_RESULTS.md)
  не подтвердил существенный выигрыш кейса 2. При единственном обучающем номинале
  8 мм OOF вообще не различает абсолютную и относительную потерю, хотя запросные
  прогнозы отличаются до 1,37 мм. Для выбора нужны разрешённые независимые данные.
- `missing_policy`: `observed-only` по умолчанию или `train-median`.
- `rate_regularization=0.25`, `robust_delta_mm=0.5`, `residual_alpha=100.0`,
  `scale_regularization=1.0`, `max_nfev=2000`. Неизвестные параметры отклоняются.
- Скорость `exp(a + beta*z)` в мм/год. z: water, temperature, log1p(velocity), fill
  после train-only импутации/стандартизации. Фиксированные границы a: -18..ln(10),
  beta: -2..2, z: -5..5. Все настройки и коэффициенты отражены в diagnostics_.
- Полностью отсутствующий канал заполняется фиксированным 0 и отмечается в
  `empty_training_channels`. Это техническая константа, не восстановленный режим.
- Параметрическая скорость требует наблюдаемых тренировочных TECH-дней.
  Если наблюдаемая экспозиция целиком нулевая, observed-only не идентифицируется.
  Константная скорость train-median может калиброваться по календарю без TECH.
- Остаточная поправка Ridge обучается на знаковой ошибке в мм/год и умножается
  на горизонт при predict. Между ВТД обе компоненты обучаются только с якорем.
- Дополнительный hybrid_scale умножает физическую потерю на exp(g(features)).
  Признаки стандартизованы на train, коэффициенты и интерсепт регуляризованы,
  log-множитель ограничен диапазоном -5..5. Скрытая потеря остаётся неотрицательной.

## Уточнения канонических входов

- Неизвестный день: observed=false, available_at=NaT, физические каналы NaN.
  Нулевой поток/скорость в наблюдаемый день не меняет observed=true.
- Температурные заглушки чистит общий cleaner. Отрицательные °C здесь допустимы.
- Наивные даты трактуются как Europe/Moscow, timezone-aware переводятся в неё.
  Окна начинаются и заканчиваются в полночь. Доступность метки не раньше target,
  доступность TECH не раньше своего дня. Смешанные timezone в столбце нормализует
  общий конвейер.
- При неизвестном якоре возвращается fallback_mm без коррекции или отсечки.
  Fallback вычисляет общий конвейер только по разрешённому train.
- Feature_columns — доверенный явный общий allowlist. Известные целевые/ключевые
  имена и история ВТД для cold дополнительно запрещены. Происхождение произвольно
  переименованных признаков обязан проверять общий конвейер.

## Диагностика и подключение

Остаточный гибрид возвращает сырой прогноз, включая возможные отрицательные или
выше номинала значения. Единый диапазон [0, nominal_mm] применяет общий оценщик.
Физическая компонента имеет естественный нижний предел 0. В last_prediction_
сохраняются sample_id, сырой прогноз, физический прогноз, интеграл и used_fallback.
При fallback физический прогноз/интеграл имеют NaN, итоговый прогноз конечен.
Diagnostics_ сериализуется в JSON; сам объект через joblib сохраняет и exposure.

Основному агенту необходимо:

1. Добавить в реестр agent2_constant_rate, agent2_positive_rate,
   agent2_hybrid_residual и agent2_hybrid_scale, передавая фабрике имя без префикса.
2. Для каждого кейса/сценария/фолда создавать отдельный экземпляр. Кейс 1:
   between, cutoff 2023-12-01. Кейс 2: cold, cutoff 2022-07-01.
3. Предоставить очищенные входы, allowlist, fallback, общий fold_id и score_mask.
4. Включить папку тестов в общий запуск: сейчас она вне стандартного testpaths.
   Проверки прошли на прямых версиях requirements.txt; при необходимости
   воспроизвести также весь транзитивный lock и целевой Python 3.12.
5. Сохранять общие ключи, исходные/ограниченные прогнозы, параметры и время fit;
   подключить scorer, графики и экспорт после проверки.

Пакет не строит свои цели, фолды, loader и маску, не запускает старый benchmark
как замену проверке 1.0.0 и самостоятельно не включается в общий реестр.

## Второй этап: явный контроль экстраполяции остаточного гибрида

Задание: docs/reviews/agent2-0873f69.md; общая база обновлена до d443e4f.
Исходный `hybrid_residual` сохранён: по умолчанию `residual_guard="none"`.
Новый вариант включается через ту же фабрику и то же имя:

```python
options = {
    "missing_policy": "observed-only",  # отдельно сравнивается train-median
    "residual_guard": "train-bounded",
    "residual_z_limit": 3.0,
    "residual_min_relative_scale": 1e-6,
}
```

Импутация, индикаторы пропусков, средние, дисперсии и выбор признаков обучаются
только на допустимых калибровочных train-строках. Признак отключается при
std <= 1e-6 * max(1, abs(mean)), остальные нормированные входы ограничиваются
[-3, 3] и при fit, и при predict. При отсутствии оставшихся признаков Ridge
оценивает только интерсепт. Физическая компонента и формула мм/год не меняются.
Настройки зафиксированы до нового реального сравнения, поиска по меткам цели нет.

Ограничивается экстраполяция входов, итоговая толщина не отсекается внутри
гибрида. `diagnostics_["residual_guard"]` содержит обученные статистики,
отключённые признаки, число ограниченных строк/значений, максимальный исходный
|z| и сдвиги отключённых признаков. `last_predict` относится к последнему вызову.

Сравнение использует `pipetwin.case_experiments.run_case` без изменения loader,
маски, scorer, общих фолдов и диапазона прогноза:

```powershell
python -m pipetwin.agent2_physics.shared_comparison --prepared artifacts/agent2_physics/shared-inputs-d443e4f --output artifacts/agent2_physics/shared-comparison-v2
```

В этом wrapper зафиксированы два missing_policy, исходные четыре физические
модели и новый режим остаточного гибрида. Контроли: общие persistence,
global_rate, GAM и CatBoost. Результаты сохраняются с `missing_policy` и
`variant`; общий API/реестр новых имён не требует. Для включения в основной
рейтинг нескольких вариантов одного имени основной агент добавляет именованную
конфигурацию, передающую указанные options. Общие файлы агент 2 не меняет.

### Итог реального сравнения

Результаты сохранены в `artifacts/agent2_physics/shared-comparison-v2/`, протокол
и таблицы опубликованы в `RESULTS.md`. 211 общих тестов прошли с `-W error`.
Исходные четыре модели и guard сравнены в observed-only и train-median через
общий run_case; ключи, даты, fold_id и observed-маска проверены после записи CSV.
Повторная загрузка всех 36 финальных моделей воспроизвела сохранённые прогнозы.

- Case1: guard улучшает residual (MAE 0.424523 -> 0.389183, r² 0.053932 ->
  0.144045), но уступает общим CatBoost/GAM. Предлагается отдельная конфигурация
  кандидата для сравнения, без автоматического изменения победителя/смеси.
- Case2: исходный residual в обоих missing_policy даёт 100% прогнозов выше
  номинала. Guard устраняет насыщение, но OOF r отрицателен и MAE не улучшена.
  Исходный residual не рекомендуется как финальный предиктор, а guarded-вариант
  остаётся исследовательским. Допустимый диапазон не подтверждает точность.
- Все строки с физическим якорем case1 и все строки case2 задействовали guard:
  значительный сдвиг входов сохраняется в диагностике, а не скрывается отсечкой.
- Финальные диапазоны cold между missing_policy различаются примерно на 0.75 мм
  при почти одинаковом OOF. Результаты не разрешают неопределённость ранней истории.

Общая политика выбора, набор входов, реестр, ансамбли и экспорт — ответственность
основного агента. Не следует переносить лучшую картинку целевого профиля в критерий
выбора или объединять два fitted-кейса. Время/метрики по вариантам, raw/bounded
прогнозы и train-only параметры доступны в сохранённых артефактах.
