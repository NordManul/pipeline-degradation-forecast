# Контракт модельного компонента 1.0.0

Владелец интерфейса — основной агент. Реализация второго агента находится в `pipetwin.agent2_physics`. Общий конвейер передаёт уже нормализованные, очищенные и ограниченные во времени данные. Фабрика не читает CSV, не строит собственные цели и фолды.

## Публичная фабрика

```python
make_model(
    name,
    *,
    scenario,               # "between" или "cold"
    exposure,               # каноническая таблица ежедневных экспозиций
    cutoff_exclusive,       # ISO timestamp, отдельный для каждого кейса
    feature_columns,        # явный общий allowlist для ML-поправки
    seed=42,
    options=None,           # missing_policy, регуляризация и другие сохранённые настройки
)
```

Фабрика возвращает объект с `fit(frame, y_mm) -> self`, `predict(frame) -> np.ndarray` и сериализуемым словарём `diagnostics_` после fit. `predict` возвращает ровно `len(frame)` конечных чисел в миллиметрах, в исходном порядке строк. Перестановка frame должна переставлять прогнозы соответствующим образом.

Имена обязательных моделей: `constant_rate`, `positive_rate`, `hybrid_residual`. `hybrid_scale` — дополнительная после обязательных проверок. Основной реестр добавит префикс `agent2_`, чтобы не конфликтовать с существующими моделями.

## Таблица frame

Одна строка — сегмент конкретного исторического примера или запроса прогноза. Повторный сегмент в разных кампаниях имеет разные `sample_id`.

| Поле | Смысл и тип |
| --- | --- |
| `sample_id` | Уникальная непустая строка в данном frame; ключ выравнивания результатов и меток. |
| `id`, `main_id`, `segment_id` | Строковые ID и целый номер сегмента. Метаданные, не автоматические регрессионные признаки. |
| `scenario` | Единый для вызова `between` или `cold`, совпадает с фабрикой. |
| `target_date` | Дата измеряемого состояния этого примера, не позже case cutoff. Для fit это разрешённая историческая дата метки. |
| `label_available_at` | Только в fit: доступность метки, строго меньше case cutoff. При более поздней известной публикации используется именно она. |
| `window_start`, `window_end` | Границы календарного интеграла `[start, end)`. Для between — от прошлого ВТД, для cold — от согласованного ввода. `window_end=target_date` в текущем контракте. |
| `horizon_years` | Положительная календарная длительность в сутках / 365,25. |
| `nominal_mm` | Положительный доступный паспортный номинал для соответствующей эпохи металла. |
| `anchor_mm`, `anchor_observed` | Для between: известное прошлое измерение и булев флаг. Значение при false может быть техническим заполнителем, но не является наблюдением для калибровки роста. |
| `anchor_date` | Для between строго меньше target; у cold отсутствует. |
| `exposure_id` | Ссылка на историю конкретного ID и окна. Несколько сегментов могут ссылаться на одну историю. |
| `fallback_mm` | Предварительно рассчитанный основным конвейером резервный прогноз по разрешённому train. Используется для between-строк без наблюдаемого якоря. |
| остальные разрешённые признаки | Только имена из переданного `feature_columns`; их единицы фиксируются общим конвейером. |

`y_mm` передаётся отдельно от frame, позиционно в том же порядке, конечные положительные метки. `y_mm`, толщина/геометрия целевого ВТД, его число дефектов и покрытие не входят в `feature_columns`. Прогноз не зависит от наличия диагностических столбцов с метками: они никогда не выбираются в матрицу признаков.

## Таблица exposure

| Поле | Правило |
| --- | --- |
| `exposure_id`, `id` | Идентификатор истории и простой участок. Группировка интегралов по `exposure_id`, **не только по id**: у одного участка могут быть разные исторические окна. |
| `day` | Каждый календарный день окна один раз. Дубли `(exposure_id, day)` запрещены. |
| `available_at` | Для наблюдаемой записи — время доступности выбранного снимка; для неизвестного дня — NaT. |
| `observed` | Есть ли реальная запись TECH, отдельно от нулевого расхода. |
| `dt_years` | 1 / 365,25 для выбранной дневной конвенции. Сумма по истории равна horizon_years. |
| `water_fraction` | Доля 0…1 или NaN. |
| `temperature_c` | Температура в рабочей интерпретации °C или NaN; обработка заполнителей уже выполнена общим конвейером. |
| `velocity_m_s` | Неотрицательная допустимая скорость жидкости или NaN. |
| `fill_coefficient` | Доля 0…1 или NaN. |

Основной агент строит эту таблицу; второй агент проверяет ключи, диапазоны, границы дат и длительности. Для каждой истории `window_start <= day < window_end <= case cutoff`. Наблюдаемое `available_at` должно быть раньше соответствующего `window_end` и case cutoff. Одинаковая сумма дней при неверных календарных датах не считается корректной историей.

Общая exposure может содержать разрешённые истории нескольких фолдов. В `fit` любые обучаемые преобразования используют **только exposure_id, на которые ссылается train frame**, и только наблюдаемые дни для определения обучающих медиан. При многократной ссылке сегментов на ту же историю не умножать её дни при расчёте preprocessing. В `predict` применяются сохранённые преобразования.

## Сценарии и физический смысл

- `between`: калибровка физической потери только по `anchor_observed=true`. Исходная знаковая разность `anchor_mm-y_mm` сохраняется; отрицательные измеренные разности не заменяются нулём в обучающей цели. Ненаблюдаемый якорь не подменяется номиналом для обучения скорости.
- `between` без прошлого измерения: вернуть `fallback_mm` для этой строки. Не удалить строку и не приписать ей физически измеренную начальную толщину. Если в train нет ни одного допустимого наблюдаемого якоря — понятная ошибка непригодности модели, которую обрабатывает общий конвейер.
- `cold`: начальный уровень — разрешённый `nominal_mm`, окно — ввод→дата примера. Прошлое ВТД и признаки его наличия не используются. Параметры обучаются только на разрешённых cold-примерах соответствующего case cutoff; модель из кейса 1 не переносится готовым fitted-объектом в кейс 2.
- Потеря физической компоненты — интеграл неотрицательной скорости в мм/год. Модель является калиброванной параметрической аппроксимацией, а не подтверждённой механистической моделью CO₂-коррозии.
- `missing_policy=observed-only`: неизвестные дни не добавляют наблюдённой экспозиции; это нижний сценарий экспозиции, а не утверждение о нулевой коррозии.
- `missing_policy=train-median`: неизвестные дни заполняются обучающим режимом. Это явное сценарное допущение, не восстановленная истина.
- Остаточный гибрид может дать толщину выше прошлого измерения. Для диагностики сохраняется исходный прогноз. Единая окончательная отсечка до `[0, nominal_mm]` выполняется общим оценщиком, а не отдельной скрытой политикой каждой модели. Внутренняя монотонная физическая компонента может иметь естественную нижнюю границу 0.
- На первом этапе P и Q gas не входят в физический закон: подтверждённые единицы не закрывают абсолютность давления и условия приведения газа.

## Диагностика и воспроизводимость

`diagnostics_` содержит имя модели, scenario, contract_version, cutoff, seed, options, число обучающих строк/историй/наблюдаемых дней/отброшенных якорей, параметры и статус оптимизации, список признаков, число fallback-строк при последнем predict. Записывать время fit отдельно в отчёте запуска. Сохранение через joblib и повторная загрузка должны воспроизводить прогноз в численном допуске.

Каждый эксперимент использует общий `fold_id`, одинаковые ключи и score_mask. В итоговой таблице прогнозов сохраняются `case_id, sample_id, id, segment_id, target_date, fold_id, model, prediction_mm` и версия контракта. Метрики считает общий конвейер.

## Обязательные проверки реализации второго агента

1. Сутки→годы, високосный год, отсутствие повторного учёта дней и корректное совпадение интеграла с постоянной скоростью.
2. Две истории одного ID с разными окнами не смешиваются. Изменение порядка строк не меняет привязку прогноза.
3. Будущая/однодневная после cutoff запись и неверно датированная история отклоняются; случай case2 2022-07-06 не проходит как доступная метка.
4. Импутация и стандартизация не меняются от добавления/изменения exposure, которая относится только к validation. Общие прошлые режимы одного ID допустимы, когда действительно доступны train-примерам.
5. Отрицательная наблюдаемая потеря остаётся в функции ошибки; физическая прогнозная скорость неотрицательна.
6. Номинальная подстановка при `anchor_observed=false` не участвует в калибровке between; предсказание возвращается для всех строк через объявленный fallback.
7. Cold-компонент работает без предыдущего ВТД и не использует его столбцы; отдельные модели/преобразования у двух кейсов.
8. Оба сценария неизвестных дней различимы в настройках и результатах; нулевой поток не превращается в неизвестный день.
9. Гибрид прогнозирует без целевых меток, не меняет маску оценки, сохраняет конечные значения и воспроизводится после сериализации.

Тесты нового модельного поведения пишет второй агент в собственной папке. Общие тесты очистки, единиц, сетки, фолдов и экспорта остаются у основного агента.
