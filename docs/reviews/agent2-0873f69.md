**76 passed in 7.67s**, с предупреждениями как ошибками. Это синтетические проверки.

Подтверждены: отдельные case-cutoff, запрет будущих меток, группировка по exposure_id,
train-only preprocessing, отсутствие калибровки between на номинальных подстановках,
сохранение знаковых разностей и сырых прогнозов остаточного гибрида.

## Существенная проблема переноса

Пробный final fit использовал только разрешённый train, missing_policy=observed-only,
фиксированные значения параметров. Истинные целевые ВТД отсутствуют: таблица ниже —
**диагностика выходов, не оценка точности и не рейтинг**.

| Кейс | Модель | Минимум / максимум сырого прогноза, мм |
| --- | --- | --- |
| 1 | constant_rate | 3.50384 / 7.18384 |
| 1 | positive_rate | 3.50384 / 7.18384 |
| 1 | hybrid_residual | -1.90951 / 6.32000 |
| 1 | hybrid_scale | 3.50441 / 7.18354 |
| 2 | constant_rate | 2.26812 / 2.26812 |
| 2 | positive_rate | 2.29482 / 2.29482 |
| 2 | hybrid_residual | 27.35731 / 30.63558 |
| 2 | hybrid_scale | 2.03378 / 2.51157 |

У case2 номинал 4,5 мм. Все 1475 прогнозов `hybrid_residual` превышают номинал,
поэтому после общего ограничения результат станет константой 4,5 мм. В rate-части
нормированные каналы ограничены, а в остаточной Ridge-поправке экстраполяция входов
не ограничена. Это проблема пригодности конкретного варианта при переносе,
а не нарушение контракта возврата сырого прогноза.

Компоненты допустимы к интеграции и общей проверке. Остаточный гибрид нельзя считать
готовым финальным решением только потому, что тесты интерфейса прошли.

## Следующее задание второму агенту

1. Обновить общую базу до опубликованного коммита с `prepare-cases` и прочитать
   [описание пакетов](../case-inputs.md). Общие входы уже сформированы локально в
   `artifacts/official-inputs-20261114-v1/`; на другом checkout воспроизвести одной командой.
2. Выполнить реальное сравнение четырёх моделей в двух сценариях неизвестных дней
   на **тех же четырёх фолдах**, маске и ключах. Для fit брать observed-строки.
   Сохранить OOF, сырые/ограниченные final прогнозы, времена, параметры и насыщение.
3. Добавить один явно включаемый устойчивый вариант остаточного гибрида, сохранив
   исходный для сравнения. Приоритет — train-only контроль почти постоянных признаков
   и/или ограничение нормированных входов поправки. При необходимости отдельной
   ограниченной абляцией проверить поправку в долях номинала в год для cold.
   Не подбирать границы по скрытым целевым меткам и не заменять проблему одной отсечкой толщины.
4. Добавить тест на сильный сдвиг режимных входов при номинале 4,5 против обучающих 8 мм:
   у нового варианта диагностировать экстраполяцию и убедиться, что предохранитель
   обучается только на train. Сохранить проверки изоляции будущего, fallback и сериализации.
5. Зафиксировать итог в своей `RESULTS.md`: OOF и диапазоны прогнозов раздельно,
   ограничения независимой проверки и конкретное предложение по использованию модели.

Не расширять набор семейств и не менять общий loader, маску, фолды, scorer или экспорт.
Основной агент параллельно завершает общий benchmark и E04. Даже физически допустимый
диапазон сам по себе не доказывает точность на неизвестном ВТД.
